本页说明「GitHub 加速节点检测」工具的全部功能与常见问题。

🚀 快速上手

  1. 打开检测页（index.html），页面会自动检测全部 33 个加速节点；也可点击「▶ 全部检测」手动触发。
  2. 看状态列：可用 的节点可放心使用；「延迟」列数值越小越快。
  3. 需要下载 GitHub 资源时，把「加速前缀」拼在原始链接前，或使用页面底部的链接加速转换直接生成。

加速链接的基本公式：加速前缀 + 完整 GitHub 链接

例如原始链接为 https://github.com/git/git/archive/refs/tags/v2.43.0.tar.gz，
加速链接即 https://ghfast.top/https://github.com/git/git/archive/refs/tags/v2.43.0.tar.gz

更多支持的链接类型（Releases / Raw / Archive / Blob / Gist / clone 等）见 gh-proxy 官方文档。

🔍 检测原理与状态说明

浏览器直接请求 代理地址 + 目标文件（默认拉取 github/gitignore 仓库的 README）：

  1. 先发带 CORS 的请求 —— 能读取 HTTP 状态码并校验文件内容；
  2. 若被 CORS 拦截，退回 no-cors 探测 —— 只能确认服务器是否可达。
状态含义建议
可用 代理返回 2xx 且内容校验通过，完全验证 放心使用
可达 服务器有响应，但未开启 CORS，浏览器内无法验证代理内容 并非不可用！请在下载工具中实际验证
HTTP xxx 代理返回了错误状态码（404 / 429 等），原因见该节点 可稍后重试或换节点
不可用 DNS 解析失败 / 连接失败 / 超时 当前网络下无法使用

🧩 节点分组：前缀型 与 替换型

两类节点的用法不同，页面按此分组展示：

① GhProxy 前缀型（32 个）

在原链接前面拼接前缀：

  • 下载：https://ghfast.top/https://github.com/owner/repo/releases/download/…
  • 克隆：git clone https://ghfast.top/https://github.com/owner/repo.git

② 域名替换型（1 个：xget.xi-xu.me/gh）

把链接中的 github.com 替换为镜像域名：

  • https://github.com/owner/repo/... → https://xget.xi-xu.me/gh/owner/repo/...

页面的「链接加速转换」会对两类节点自动采用正确的拼接方式，无需手动区分；逐行「复制前缀」时请注意替换型节点需自行替换域名。

⚙️ 检测目标与测速文件

  • 检测目标：默认为 github/gitignore 仓库的 README。换成你要下载的实际文件，测出的可用性更贴近真实场景。
  • 测速文件：默认为 git 仓库 v2.43.0 的源码归档（几 MB，不可变）。文件越大测速越稳定，最多取 20 秒。
  • 两项均支持任意 http(s) 地址，保存在浏览器本地。

❓ 常见问题

「可达」的节点能用吗？为什么不算「可用」？

能。这些节点只是没有开启 CORS 响应头，浏览器出于安全策略不允许页面读取响应内容，所以无法自动验证。用 curl / wget / 浏览器直接下载时不受 CORS 限制，实际多半可用。

为什么有的节点显示 HTTP 404 或 429？

404 通常是该节点不支持当前检测目标的路径格式（例如只代理 github.com 域名、不代理 raw 域名）；429 表示触发了节点限流。可以在 ⚙️ 配置里换一个检测目标再试。

延迟 / 速度和我实际体验不一致？

所有数据都是本机网络视角的一次采样：不同地区、运营商、时段结果不同；小文件延迟包含握手与首字节时间；测速受节点缓存影响（命中缓存会偏快）。建议多测几次取趋势。

支持哪些 GitHub 链接类型？

Releases 附件、源码归档（archive）、raw 文件、blob 页面自动转 raw、Gist、git clone 等，多数节点都支持；个别节点的支持范围以其自身实现为准。私有仓库不在公共节点支持范围内。

怎么让 git 全局自动走加速？

以 gh-proxy.org 为例（前缀型节点同理）：

git config --global url."https://gh-proxy.org/https://github.com/".insteadOf "https://github.com/"

取消时把 --global 换成 --unset 重复执行即可。

节点列表是怎么来的？可以自己增删吗？

收录自社区公开汇总（如 hunshcn/gh-proxy#116、XIU2/UserScript 内置站点列表），并经过连通性与内容双重核验。编辑 index.html 中的 SERVICES 数组即可增删；非前缀型节点需在 NODE_TYPES 标注类型。

会收集我的数据吗？

不会。纯静态单文件页面，无后端、无统计；所有配置只保存在你浏览器的 localStorage 里，检测请求由你的浏览器直接发往各节点。

⚠️ 注意事项

  • 公共加速节点仅供学习、科研与正常开源下载，请合理使用，勿滥用或用于违规内容。
  • 公共节点时效性强，随时可能失效或更换域名，检测结果仅供参考。
  • 仅加速公开资源，私有仓库需自建节点并配置凭据。
